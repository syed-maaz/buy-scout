# buy-scout documentation site

## System Overview

Docusaurus 3.10.2 documentation site and landing page for the buy-scout POC.
`docusaurus.config.ts` sets `title: "buy-scout"`, the tagline "A reusable
buy-side search engine, starting with a family car", `baseUrl: "/"`, and a
placeholder public origin `https://buy-scout.local`. Content comes from the
classic preset with `docs.path: "docs"`, `routeBasePath: "docs"`, `blog: false`
and `theme.customCss: "./src/css/custom.css"`; Mermaid is enabled through
`markdown.mermaid` plus `@docusaurus/theme-mermaid`, and local search through
`@easyops-cn/docusaurus-search-local` (`hashed: true`, `docsRouteBasePath:
"/docs"`, `indexBlog: false`).

Developer notes (preserved):

```bash
cd buy-scout
npm run docs:dev      # http://127.0.0.1:3100
npm run docs:build
npm run docs:serve    # serve the built site
```

`website/docs` is a build-time copy of the canonical `docs/` directory.
`docs:dev` and `docs:build` run `docs:sync` first; edit the root docs, not
the copy. The generated site is in `website/build/`.

## Local Interface & Invariants

- `docusaurus.config.ts` — `export default config: Config`. Navbar:
  `docSidebar` item with `sidebarId: "docs"` (label "Documentation") and a
  right-side `to: "/docs/ui"` link ("Run the UI"). Footer columns "Docs"
  (`/docs/intro`, `/docs/architecture`, `/docs/smart-fetch`) and "Operations"
  (`/docs/operations`, `/docs/sources-operations`, `/docs/verdicts`).
  `onBrokenLinks: "warn"`, `favicon: "img/logo.svg"`, prism themes
  `github`/`dracula`, copyright interpolating `new Date().getFullYear()`.
- `sidebars.ts` — `export default sidebars: SidebarsConfig`, a single sidebar id
  `docs`: top-level `intro`, then categories "Start here" (`architecture`,
  `data-model`), "Decide" (`criteria`, `verdicts`, `analysis`), "Run it" (`ui`,
  `operations`, `sources-operations`, `mobile-de-latency`), "Quality"
  (`evaluation`, `roadmap`), and "Reference" (`glossary`, `journal`, an
  "Architecture decisions" category with `adr/adr-0001` + `adr/adr-0002`, and a
  collapsed "Legacy & deep dives" category listing `status`, `smart-fetch`,
  `sources`, `workarounds`, `access-playbook`, `criteria-flow`, `runbook`,
  `plan`, `acceptance`, `backlog`).
- `package.json` — internal site manifest (`buy-scout-docs`) with scripts
  `start`, `build`, `serve`, `clear` invoking the `docusaurus` CLI; no `test`
  script.
- `tsconfig.json` — extends `@docusaurus/tsconfig` with `baseUrl: "."`.
- [src](./src/README.md) — routes and theme overrides.
- `static/img/logo.svg`, `static/img/buy-scout-desktop.png`,
  `static/img/buy-scout-mobile.png` — static assets served at `/img/*`
  (unlinked here; not contract directories).

## Subdirectories & System Boundaries

- [src](./src/README.md) — landing-page route (`src/pages`) and global theme
  overrides (`src/css`); presentation only, no buy-scout domain logic.
- `docs` — generated build-time copy of the repository `docs/` tree, produced by
  `docs:sync` (`rm -rf website/docs && cp -R docs website/docs`). Git-ignored;
  deliberately not documented as a contract — edit the root `docs/` instead.
- `build` — generated static site output of `docusaurus build`. Git-ignored; not
  documented.
- `static` — static assets directory (images/logo only, no source modules); not
  documented.
- `.docusaurus` — generated Docusaurus cache. Git-ignored; not documented.

## Global Invariants

- Single source of truth for prose is the repository-root `docs/` directory.
  `website/docs` is deleted and re-copied on every `docs:dev`/`docs:build`, so
  edits made inside `website/docs` are lost.
- `sidebars.ts` entries are doc **ids**, taken from each page's frontmatter
  `id:` (for example `docs/INTRO.md` declares `id: intro`, which is what
  `sidebars.ts` lists), not from the uppercase filenames. Renaming or deleting a
  doc without updating `sidebars.ts` breaks the sidebar build; a navbar/footer
  `to:` target that no longer exists only warns, because `onBrokenLinks` is
  `"warn"`.
- Build the site through the repository root scripts (`npm run docs:build`,
  `npm run docs:dev`) — they run `docs:sync` first. Invoking
  `npm --prefix website run build` directly can bundle a stale `website/docs`
  copy.
- `url`/`baseUrl` are local placeholders (`https://buy-scout.local`, `/`); the
  site is not configured for a real deployment origin, and search/SEO output
  inherits that.
- Site text must stay descriptive: operational numbers (counts, scores,
  verdicts) are generated by `npm run health` / `npm run eval` in the root
  project, not hard-coded in the site.

## Global Side Effects

- `docs:sync` (root script) recursively deletes `website/docs` and copies
  `docs/` into it — destructive to any in-place edits in the copy.
- `docusaurus build` writes `website/build/` and refreshes the
  `website/.docusaurus/` cache; `docusaurus clear` deletes that cache.
- `docusaurus start` / `serve` bind a local HTTP server (root scripts pin
  `127.0.0.1:3100`).
- The local search plugin builds a hashed client-side search index from the
  synced docs at build time — no external search service is contacted.
- `docusaurus.config.ts` evaluates `new Date().getFullYear()` at config load, so
  the emitted copyright year tracks build time, not source time.

## System Verification

- Run: `npm test` from the repository root (buy-scout suite;
  `tsx --test tests/*.test.ts` — does not exercise the site).
- Run: `npm run docs:build` from the repository root (`docs:sync` then
  `docusaurus build`) — the real check for these contracts; a failure here means
  broken routes, sidebar ids, or styles.
